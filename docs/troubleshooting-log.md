# Git 트러블슈팅 기록

[시작 안내](../README.md) · [실습 절차](../reference/B2-2-scenarios.md#practice)

**A는 T1, B는 T2, C는 T3, D는 T4만 작성합니다.**
실습 명령의 출력을 복사해 아래 빈 항목을 채우고, 본인의 두 번째 PR에 포함합니다.
SHA는 `git rev-parse HEAD`가 출력하는 커밋 식별자입니다. 원격 공개 전후 상태도 함께 적습니다.

**상태: 팀 실습 미수행.** 다음 4개 기록에 실제 이름과 참여 역할을 반드시 남깁니다.
예상 결과는 증빙이 아닙니다. 실제 명령과 출력, 전후 SHA, 원격 반영 여부를 구분합니다.

## T1 · commit --amend

- 상태: 미수행
- 수행자 / 기록자: A / A (실명으로 교체)
- 상황: 브랜치·원격 공개 전 여부·수정할 메시지
- 실제 명령과 출력: 미기입
- 전후 상태: 이전/새 커밋 SHA·메시지, 이전/새 tree SHA
- 결과: 메시지 변경 및 파일 내용 동일 여부
- 선택 이유: 새 커밋 추가 대신 amend를 사용한 이유
- 주의점: 공개된 커밋 재작성 시 동료 작업에 미치는 영향
- Issue / PR / 증빙: 미기입

## T2 · reset --soft HEAD~1

- 상태: 미수행
- 수행자 / 기록자: B / B (실명으로 교체)
- 상황: 취소할 미공개 커밋·부모 커밋·작업 트리 상태
- 실제 명령과 출력: 미기입
- 전후 상태: HEAD, staged 변경, reset 전 tree SHA와 reset 후 write-tree 결과
- 결과: 커밋 취소·변경 유지·재커밋 여부
- 선택 이유: soft와 다른 reset 모드의 차이
- 주의점: 공유 브랜치에서 수행하지 않은 이유
- Issue / PR / 증빙: 미기입

## T3 · revert

- 상태: 미수행
- 수행자 / 기록자: C / C (실명으로 교체)
- 상황: README 끝에 임시 안내를 추가해 원격 feature 브랜치에 공개한 커밋
- 실제 명령과 출력: 미기입
- 원격 공개 증빙: fetch 후 `git branch -r --contains` 결과와 원본 커밋 URL
- 전후 상태: 원본 커밋 SHA, revert 커밋 SHA, 파일 상태
- 결과: 이전 기록 유지·취소 커밋 추가·원격 업데이트 여부
- 선택 이유: 공개된 커밋에 reset 대신 revert를 적용한 이유
- 주의점: 이번 대상은 일반 커밋이며 merge 커밋 취소와 다름
- Issue / PR / 원본·취소 커밋 URL: 미기입

## T4 · stash / stash pop

- 상태: 미수행
- 수행자 / 기록자: D / D (실명으로 교체)
- 상황: README 실행 예시를 Git 입력으로 수정하던 중 다른 브랜치 확인 필요
- 실제 명령과 출력: 미기입
- 전후 상태: stash 전 diff, stash 목록, 전환 후 상태, pop 후 diff
- 결과: 원래 변경 복구 여부·stash 잔존 여부
- 선택 이유: 임시 커밋 대신 stash를 사용한 이유
- 주의점: 새 파일 포함 여부와 pop 충돌 시 처리
- Issue / PR / 증빙: 미기입
