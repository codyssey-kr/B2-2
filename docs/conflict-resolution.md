# 충돌 해결 기록

[시작 안내](../README.md) · [실습 절차](../reference/B2-2-scenarios.md#practice)

**B는 [본인 실습](../reference/B2-2-scenarios.md#practice-b)에서 #1, D는 [본인 실습](../reference/B2-2-scenarios.md#practice-d)에서 #2만 작성합니다.** 상대 팀원의 기록은 유지합니다.
해결 커밋을 만든 뒤 그 SHA와 PR URL을 추가 커밋으로 남겨도 됩니다.

**상태: 팀 실습 미수행.** 아래는 기록 양식입니다. 예상 과정은 [시나리오](../reference/B2-2-scenarios.md#practice)를 참고하고,
실제로 수행한 명령·출력·링크만 이 문서에 기록합니다.
충돌 마커를 기록할 때는 코드 울타리와 내용의 각 줄 앞에 `> `를 붙이고 줄 끝 공백을 제거합니다.
일반 코드 블록의 마커도 `git diff --cached --check`에서는 미해결 충돌로 잡힙니다. [시나리오의 인용 예시](../reference/B2-2-scenarios.md#practice-b)를 따릅니다.

## 충돌 #1 · README 소개 문장의 같은 줄 수정

- 상태: 미수행
- 참여자: A(상대 변경 작성자), B(해결·기록 담당) — 실제 이름으로 교체
- 관련 Issue / PR: 미기입
- 기준 SHA / 양쪽 브랜치 / 충돌 직전 SHA: 미기입
- 대상 파일: `README.md`의 소개 문장
- 상황: 실제 변경 내용과 각각의 목적을 기입
- 재현 절차: 실행한 명령을 순서대로 기입
- 충돌 내용: 실제 `git status`, `git diff`, 충돌 마커를 코드 블록으로 첨부
- 해결 전략과 이유: 두 요구사항 중 보존·변경한 부분과 합의 이유를 기입
- 해결 명령과 최종 내용: 미기입
- 검증: unmerged 파일이 없는지, 문서·사용 예시 실행 결과를 기입
- 결과: 해결 커밋 / 병합 PR URL / 상대 확인 스레드 링크
- 배운 점과 예방책: 미기입

## 충돌 #2 · README 실행 예시의 같은 줄 수정

- 상태: 미수행
- 참여자: C(상대 변경 작성자), D(해결·기록 담당) — 실제 이름으로 교체
- 관련 Issue / PR: 미기입
- 기준 SHA / 양쪽 브랜치 / 충돌 직전 SHA: 미기입
- 대상 파일: `README.md`의 공통 함수 실행 명령·예상 출력
- 상황: Python 예시와 Git 예시로 각각 바꾼 의도를 기입
- 재현 절차: 실행한 명령을 순서대로 기입
- 충돌 내용: 실제 `git status`, `git diff`, 충돌 마커를 코드 블록으로 첨부
- 해결 전략과 이유: 두 실행 예시와 각 예상 출력을 어떻게 함께 보존했는지 기입
- 해결 명령과 최종 내용: 미기입
- 검증: README 예시 실행, unmerged 파일 없음, 공통·팀원 함수 사용 예시 실행 결과
- 결과: 해결 커밋 / 병합 PR URL / 상대 확인 스레드 링크
- 배운 점과 예방책: 미기입
